# Retro Report: Sections You Write

`brief-scan.cjs --retro` prints the report from the title through Data Notes. Drop its first line (`<!-- save as ... -->`, the file path), keep the rest unchanged and append the two sections below.

---

## Highlights

- [OK] {POSITIVE_FINDING_1}
- [OK] {POSITIVE_FINDING_2}
- [!] {NOTABLE_FINDING}

*2-4 factual observations, each naming the metric it comes from. No invented praise.*

---

## Recommendations

1. **{ACTION_1}**: {RATIONALE_1} (based on {METRIC})
2. **{ACTION_2}**: {RATIONALE_2} (based on {METRIC})
3. **{ACTION_3}**: {RATIONALE_3} (based on {METRIC})

*3-5 specific, actionable items grounded in the numbers above, for example high churn on a named hotspot, a low test-to-code ratio, or uneven activity. No generic advice. When a metric is `N/A`, do not base a recommendation on it.*

---

*Generated by `adf-brief retro` from git history*

## Rules

- Keep the report under 200 lines.
- With `--compare`, comment on the largest deltas, not every row.
- A single huge commit (an import, a vendored tree, a generated file) skews LOC and churn; when one file or commit dominates, say so in Highlights instead of drawing a trend from it.
- HTML (`--format html`): one self-contained page, inline CSS, no external scripts, fonts or images; tables keep the same rows as the Markdown.
