# Workspace

A workspace is a small git repo (manifest, `CLAUDE.md`, `.claude/`, `docs/`, `plans/`) whose members are independent, gitignored clones under role dirs. The files and their rules are in `references/workspace-files.md`.

Run every command as `node .claude/skills/workspace/scripts/workspace.cjs <command> [options]`. That line is also the entry on Windows. Common options: `--json` (exactly one JSON object on stdout, errors included), `--dry-run`, `--yes` (init, bootstrap, scaffold, sync, attach and scope settings), `--cwd <dir>`.

## When to use

- A directory holds several independent repos under role dirs and has no `adf-workspace.json` yet: `init`.
- After editing the manifest or the system map, or before relying on them: `check`.
- A fresh clone of the workspace, or a member is missing: `bootstrap`.
- The system map is missing or members were added: `seed-map`.
- A plan or task touches part of a monorepo or workspace and the session should focus there: `scope`.
- Components have no `AGENTS.md`, no `CLAUDE.md` or no service doc under `docs/architecture/services/` (`/docs init` runs this): `scaffold`.
- A member's `AGENTS.md` and `CLAUDE.md` should carry the system context of the map, or the session says "System context: N member blocks stale": `sync`.
- In a standalone clone of a member that has `.adf-workspace.json`, to give Claude access to its workspace: `attach`.

## Routing

| Command | Does | Writes |
|---|---|---|
| `init [--workspace] [--client x --product y --org a,b] [--archetype <id>] [--fix-remotes]` | Workspace mode when `--workspace` is given or role dirs hold nested repos, else monorepo mode (map only). Reports each output as `written`, `updated` or `kept`. `--archetype exchange` or `nest-service-monorepo` merges that archetype's role aliases into the new map and stores `archetype`; an existing map is kept. An unknown id exits 2. | `adf-workspace.json`, the `.gitignore` and `.ignore` blocks, `bootstrap.sh`, `docs/architecture/system-map.json`, `docs/conventions/contracts.md` (policy template, written once), `git.directPush.paths` in `.claude/config/adf-config.json` (workspace mode) |
| `check` | Validates the manifest, the map and their join, member state, ignore rules and both blocks. Exit 1 on errors; warnings do not fail. | nothing |
| `bootstrap [--pull] [--only a,b] [--allow-local] [--fix-remotes] [--protocol ssh\|https\|auto]` | Clones missing members, skips same-remote ones (or `pull --ff-only` with `--pull`). | member clones |
| `seed-map [--merge] [--archetype <id>]` | Builds the map from members or role-dir components and `contracts/*`. Without `--merge` it refuses to replace a map. `--archetype <id>` (`exchange`, `nest-service-monorepo`) merges the archetype's role aliases and stores `archetype`; with `--merge` it also applies to an existing map. `check` lists the roles and contract kinds the archetype expects and the map lacks, as information (exit unchanged). | the map |
| `scope [--plan <dir>] [--paths a,b] [--write-settings \| --clear-settings]` | Shows the scope of a plan or paths and what to load: contract consumers and producers, `worktree.sparsePaths` (monorepo), `claudeMdExcludes`, repos. Exits 1 when an entry is not a path, component name or contract id, or the list passes 50 entries (hooks ignore those too); an entry that names nothing yet is reported only. `--write-settings --yes` after the user confirms the printed diff. | `.claude/settings.local.json` only, with `--yes` |
| `scaffold [<component>] [--only agents-md\|claude-md\|service-docs]` | For each map component: a stack-specific starter in its directory and `docs/architecture/services/<name>.md` in the root docs. The starter goes in `AGENTS.md` (every agent reads it) and `CLAUDE.md` is a stub that imports it with `@AGENTS.md`. A component that already has a `CLAUDE.md` gets an `AGENTS.md` that points to it; one whose `AGENTS.md` holds ADF's installer block gets a full-starter `CLAUDE.md` instead of the stub. Each `AGENTS.md` it writes already carries the system-context block; on a workspace that was never synced, run `sync --yes` once afterwards (it writes the member markers and the block of any `CLAUDE.md` that was already there) before `sync --check` passes. `--only agents-md` on an existing workspace gives every member that has only a `CLAUDE.md` its `AGENTS.md`. Writes only files that are missing (`written` or `kept`); skips directories that are not cloned or are symlinks; `--dry-run` shows paths and first lines. | component `AGENTS.md` and `CLAUDE.md` files, service docs, with `--yes` |
| `drift [--fail-on a,b] [--allow-missing]` | Reports which ref each consumer pins per contract (submodule gitlinks, Cargo git dependencies, npm git URLs), unpinned git dependencies, and members that are not cloned. It reports; fixing drift is the project's job. Local files only, never fetches. Exit 0 unless a `--fail-on` finding exists (`differs`, `unpinned`, `not-at-local-head`, `unmapped-consumer`, `credential-in-url`, `member-missing`, `unreadable`); with `--fail-on`, a member that is not cloned also exits 1 unless `--allow-missing`. `--json` lists, per contract, `path`, `repo`, consumers and the `pinFile` of each. Policy and CI recipe: `docs/conventions/contracts.md`. | nothing |
| `repos [--plan <dir> \| --paths a,b \| --changed]` | One row per member (those in the plan or paths, every cloned member without a flag, or only those with changes) plus the workspace repo: `branch`, `staged`, `unstaged`, `untracked`, `upstream`, `ahead`, `behind`, `prBase`, `hasOwnAdf`. `prBase` comes from the member's own git flow using local refs only (no network), falling back to the manifest `branch`, then `origin/HEAD`. Members in scope that are not cloned are listed in `notCloned`. `--changed` counts any change, including an untracked `.adf-workspace.json` or a modified `CLAUDE.md` left by `sync`. Used by git-manager to commit per member. | nothing |
| `pr-links --branch <b> [--plan <dir> \| --paths a,b] [--write]` | Finds the open PRs for the branch with `gh pr list` in each repo (default: repos that have the branch locally), keeps only same-repo, non-fork ones, and prints them. `--write` puts a "Related pull requests" block (URLs and repo names) in each PR body between `<!-- adf:related-prs begin -->` and `end`; it refuses when a repo has more than one such PR and does nothing on a second run. Needs `gh`; without it the command exits 1. Repos `gh` cannot query are reported as "no PR found". | PR bodies, with `--write` |
| `sync [--member <name>] [--check] [--force] [--from <dir>]` | Writes the generated system-context block (map-derived: product, component, callers, calls, contracts, service doc) into each map component's `CLAUDE.md` and `AGENTS.md` (bullets: map facts, safety, git, PR base, rules), and in a workspace the `.adf-workspace.json` marker at each cloned member root. A `CLAUDE.md` that has the line `@AGENTS.md` gets no block: the `AGENTS.md` carries it, and a block left in that `CLAUDE.md` is removed (reported `stale` or `edited`, and failing `--check`, until then). A `CLAUDE.md` that is a symlink skips the row. An absent `AGENTS.md` is never created (`scaffold --only agents-md`); a symlinked one is skipped. Text outside the markers is untouched. Block states: `missing`, `current`, `stale`, `edited`, `outdated`. Skips a member with uncommitted changes in those files (`--force` overrides), a hand-edited block (`--force` replaces it), damaged markers (always), a component with neither file (run `scaffold`; never created) and members that are not cloned. `--check` writes nothing and exits 1 when a block or marker is missing, stale or edited (a missing `AGENTS.md` block counts when `CLAUDE.md` imports it or is absent, except in a file that holds only ADF's installer block); with no member cloned it passes vacuously, so CI must `bootstrap` first. A member with no `CLAUDE.md` still gets its marker. `--from <workspace dir>` runs inside a member and updates only that member from the workspace's map. **Sync never commits, pushes or opens a PR**: it ends with the `repos --changed` hint, and the changes go in through git-manager and the member's normal flow. Format and states: `references/workspace-files.md`. | member `CLAUDE.md`, `AGENTS.md` and `.adf-workspace.json`, with `--yes` |
| `attach <workspace-url> [--dir <path>]` | Run in a standalone member repo that has the marker. Refuses credentials, a leading `-`, and any URL whose host differs from the marker's `host` or whose owner, or the owner of the member's `origin`, is not in the marker's `org`; a refusal prints all of them. Clones the workspace next to the member (or reuses a clone with the same origin), checks the workspace lists this repo, prints the exact `settings.local.json` change. With `--yes` adds the workspace path to `permissions.additionalDirectories`. That grants file access only: no workspace `CLAUDE.md` or skills load. | the clone and `<member>/.claude/settings.local.json`, with `--yes` |

## Rules

1. `init`, `bootstrap`, `scaffold`, `sync` and `attach` only plan until `--yes` is passed (`sync --check` is read-only and needs none): without it (or with `--dry-run`) they write and clone nothing, and without `--yes` or `--dry-run` they exit 2 with the plan. Run the dry run, show the user the result, and pass `--yes` only after the user confirms (use `AskUserQuestion`). `init` prints the seeded `org` owner list with each owner's member count, a note naming every member whose owner is not in `org`, and the `git.directPush.paths` before and after: the user must confirm both, because `org` is the list of trusted owners. With `--yes` it writes `plans/**`, `README.md`, `CHANGELOG.md`, `.github/**` into the workspace's `.claude/config/adf-config.json`, keeping every other key, unless the project already set that list (then it is left alone). `docs/**` and `adf-workspace.json` stay out of the direct-push paths so they go through a pull request; `check` warns when they are in. `sync` writes into repos the team may not own day to day, and `attach` widens Claude's file access: show the dry run (for `attach`, the printed settings diff) and ask before passing `--yes`. After `sync`, tell the user it did not commit and point to `repos --changed` and git-manager. `check` and `seed-map` need no `--yes`; `seed-map` only writes a new file and refuses to replace one.
2. `init` never edits files inside a member. `--fix-remotes` only rewrites a member's `origin` to a URL without credentials.
3. Never edit member files outside a generated block. Members keep their own `CLAUDE.md`, `.claude/`, plans and hooks. `scaffold` adds an `AGENTS.md` or `CLAUDE.md` only where none exists, never edits one; `sync` edits only between its own markers, never creates an `AGENTS.md` or `CLAUDE.md`, and never creates a `docs/` folder inside a component.
4. Report failures as the command printed them. When `bootstrap` refuses a path (not ignored, symlinked, local, other remote), do not clone it another way; run `init` or ask the user.
5. `scope --write-settings` and `--clear-settings` print the exact settings diff and write nothing until `--yes`. Show the diff, pass `--yes` only after the user confirms. They touch only `worktree.sparsePaths`, `claudeMdExcludes` and `adfScope` in `.claude/settings.local.json`, never `settings.json`. Scope is advice for where to search first, not a block.
6. Output never contains credentials. If an origin holds one, `init` and `bootstrap` print the `git remote set-url` command that removes it.
